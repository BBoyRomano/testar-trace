# V1

## Purpose

This document defines the first supported behavior of ReqTrace.

It describes the minimum functional scope for the first implementation.

## Scope

ReqTrace v1 should:
- load one TESTAR-generated state model artifact
- load one requirements artifact
- analyze whether each requirement appears to have been exercised in the model
- return evidence-based per-requirement results
- return overall summary metrics

ReqTrace v1 should not yet prioritize:
- multiple input artifacts at once
- multiple matching strategies
- advanced semantic matching
- plugin discovery
- multiple UI variants

## Supported inputs

### State model artifact

V1 supports:
- one TESTAR-exported JSON artifact
- one known export structure version

### Requirements artifact

V1 supports:
- one requirements artifact
- one known structure version
- one primary requirement style

## Result statuses

V1 uses these result statuses:
- `found`
- `partially_found`
- `not_found`

## Evidence

Each requirement result must be supported by explicit evidence from the imported state graph.

V1 evidence may include:
- matched state identifiers
- matched transition identifiers
- matched observations
- explanation text

## Minimum result shape

For each requirement, V1 should return:
- requirement identifier
- result status
- supporting evidence
- short explanation

The overall result should also include:
- total requirements
- found requirements
- partially found requirements
- not found requirements

## Matching approach

The first implementation should prefer matching that is:
- deterministic
- explainable
- conservative enough to avoid misleading positive matches

## Out of scope

The following are out of scope for v1:
- support for multiple model sources
- support for many requirement formats
- confidence-based semantic matching
- persistence beyond basic export
- performance optimization beyond obvious issues
