# Presentation

## Purpose

This document defines the presentation layer.

It describes the current CLI and GUI responsibilities, input handling, result rendering, and import/export behavior.

## Boundaries

Presentation belongs in `presentation/`.

Presentation is responsible for:
- collecting run input from users
- selecting requirement and evidence inputs
- selecting a traceability method
- starting a run
- showing results
- importing saved results
- exporting completed results

Presentation is not responsible for:
- source parsing
- ingestion validation
- traceability matching or scoring
- domain-model definitions

## Current structure

```text
src/
  reqtrace/
    presentation/
      runtime.py
      cli/
      gui/
```

`runtime.py` is a thin bridge that:
- resolves requirement input paths
- builds a `TraceabilityRequest`
- executes a run through the application service
- imports/exports result JSON

## CLI

Current commands:
- `reqtrace methods`
- `reqtrace run`
- `reqtrace show-result`
- `reqtrace ui`

The CLI supports:
- one requirement file
- multiple requirement paths via repeated `--requirements`
- a requirements directory containing execution-ready markdown files
- explicit or autogenerated JSON exports

## GUI

The current GUI is a lightweight local Tkinter interface.

It supports:
- selecting requirement and evidence inputs
- selecting a method
- starting a run
- viewing summary and per-requirement results
- importing/exporting JSON results

The GUI currently uses presentation-owned background threading for responsiveness. It is not yet a full multi-run application runtime.

## Import and export

Exported results are JSON serializations of `TraceabilityResult`.

Behavior:
- if the user provides `--output`, the result is written there
- otherwise, a timestamped default path is generated
- imports read previously exported result JSON for inspection

## Current-state note

The presentation docs should reflect the implementation that exists now.

Ideas such as:
- live per-requirement progress
- cancellation
- concurrent run management
- persistent run history

are future extensions, not current guarantees.
