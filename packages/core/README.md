# TESTAR Trace Core

`testar-trace` is the core Python package for requirements traceability in state models generated by [TESTAR](https://testar.org/).

## Scope

The package provides:

- canonical domain models for requirements, state models, trace links, and analysis results;
- complete branch-resolved requirement paths;
- collections containing one or more canonical state models;
- coverage assessments at requirement-set, requirement, flow, branch, and path
  scope;
- unordered trace links and ordered path occurrences suitable for highlighting
  the original state model;
- methods for identifying trace links between requirements and state-model elements;
- analysis of requirements completeness with coverage retained as a supporting diagnostic.
- source-agnostic conversion of canonical values to plain JSON-compatible data;
- deterministic three-class evaluation against independently curated
  completeness reference labels.

Conceptually:

```text
requirements + state-model collection -> traceability method -> traceability result
```

## Package Boundary

This package contains domain models, traceability methods, and analysis logic. It does not load external requirement formats, parse TESTAR exports, or provide command-line, web, desktop, or API interfaces.

External formats are converted into the core domain models by the separate `testar-trace-adapters` package.

Built-in methods currently include:

- `noop`, which validates the pipeline without performing matching;
- `lexical`, a deterministic token-cosine baseline that returns highlightable
  per-element candidates and scoped element coverage without claiming ordered
  path completeness;
- `graph-alignment`, which aligns every materialized requirement path to one
  semantically matching, connected route in a state-model graph and assesses
  model-supported completeness;
- `execution-alignment`, which aligns paths to chronological recorded execution
  sequences and assesses observed completeness. It reports completeness as not
  assessable when no recorded sequences are available;
- `automata-conformance`, which checks requirement-path automata against the
  state-model transition system using reviewed, exact observable bindings. It
  reports completeness as not assessable when those bindings are missing,
  incomplete, or still draft.

The former `sequence` method has been removed. It compared requirement element
identifiers with state-model identifiers and therefore could not establish
semantic correspondence, graph continuity, or observed order.

Registries are explicit and isolated. `create_builtin_method_registry()` returns
a new registry for an application to extend, and `analyze_traceability` accepts
a method callable directly. Importing `testar_trace` does not mutate global
registration state.

Completeness is deliberately stricter than element coverage. A requirement is
complete only when every exhaustively materialized requirement path has one
coherent occurrence in at least one state model. Paths are never assembled from
element matches found in different models. Natural-language alignment is
heuristic; accuracy must be measured against independently curated reference
labels and is not assumed to be 100 percent. Formal conformance removes that matching
ambiguity for approved bindings, but its conclusion is only as sound as the
authored requirements, bindings, state model, and explicit conformance policy.

`evaluate_completeness` calculates exact accuracy, per-class precision, recall
and F1, macro F1, assessability rate, and a three-class confusion matrix for
collection-level assessments. It deliberately requires labels to match known
assessment scopes instead of silently dropping benchmark cases.

## Status

TESTAR Trace is under active development. The package's public Python API is not yet stable.
